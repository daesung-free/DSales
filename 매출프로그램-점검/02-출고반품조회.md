## 부수 발견

**1. 소계·총계를 SQL이 만듭니다**
```sql
case when idx is NULL and {sortCondition} is NULL then '총 계'
     when idx is NULL then '소 계' … end as '일자',
grouping(idx) as 'g1', grouping({sortCondition}) as 'g2'
```
`GROUP BY ROLLUP` 기반. 웹의 "합계는 서버가 내려준다"(§4.1) 원칙과 같은 방향입니다.

**2. `♬` 메모 분리가 조회 단에서 풀립니다**
```sql
min(replace(left(memo,charindex('♬',memo)),'♬','')) as '개별메모',
min(substring(memo,charindex('♬',memo)+1, …))      as '메모'
```
01번에서 본 저장 시 `♬` 결합의 짝입니다. **저장·조회 양쪽이 확인**됐습니다.

**3. `salesData UNION ALL invenData`** — 출고(salesData)와 입고(invenData)를 합쳐 조회합니다.
웹은 `/stock/ledger` 쪽에서 3개 union 으로 처리(문서 §주석 확인).

**4. 날짜가 varchar + 문자열 보간**
```sql
where left(tradeDate,8) between '{DateStart}' and '{DateEnd}'
```
풀스캔 + SQL 인젝션. 웹 설계가 "조회는 반드시 서버 페이징"(§4.1)인 근거입니다.

**5. 쿠폰 카운트 예외** — `CheckBox_쿠폰카운트` 체크 여부로 도서명에 '쿠폰'이 든 행의
수량을 0으로 죽입니다. **웹에 대응 기능이 없습니다.** 업무상 필요한지 확인 필요.
