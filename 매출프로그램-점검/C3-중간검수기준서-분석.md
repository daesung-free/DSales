## ★ 가장 중요한 것 — 중도금은 **화면이 아니라 엔진**으로 평가됩니다

문서 서두 원문:
> 본 프로젝트의 **50% 지점은 화면이 아니라 재고 엔진·위탁 미결정산 등 핵심 로직**이
> 완성되는 구간입니다. 이 시점에 **완성된 백오피스 화면 수는 많지 않으며**, 이는
> 타임테이블이 처음부터 그렇게 설계되었기 때문입니다.

그리고 §3.5:
> **Phase 3 선행 착수분 (참고 — 중도금 판정 대상 아님)**
> 주문/출고관리 화면군(5~11p) · 매출관리 화면군(12~20p) · 기초관리 5화면(30~36p)
> · order 신규 메뉴 4종 — **착수 사실을 보고하는 참고 항목이며 완료 여부는 잔금 검수에서 판정**

**→ 제가 지금까지 테스트한 화면 19개는 대부분 Phase 3 이라 중도금 판정 대상이 아닙니다.**
   화면 컬럼 누락 같은 항목은 **잔금 검수 사안**입니다.

## ★★ 제가 찾은 미구현이 **중도금 판정 대상**입니다

### P2-08 매입 구분값 — 🔴 중도금 항목인데 미구현

기준서 §3.4 원문:
> **P2-08 매입 구분값 필드 + 수기대사 보조**
> 8p 입고/대체등록에 '매입' 구분값 추가, 16p 순매출조회 자동 연결.
> **주문내역·판매내역 병렬 비교 보조 화면**
> — 근거: 16p 재무팀 확정(2026-07-28 정정 반영)

**점검 결과** (03번·12번):

| | 상태 |
|---|---|
| 8p 입고등록 '매입' 구분값 | ❌ **미구현** (`매입` grep 0건) |
| 16p 순매출조회 수신 준비 | ✅ 완성 (매입액(B)·이익률 컬럼 존재) |
| **수기대사 보조 화면** (주문내역·판매내역 병렬 비교) | ❓ **확인 못 함 — 존재 여부 불명** |

**이건 단순 누락이 아니라 중도금 지급을 가로막는 항목입니다.** 우선순위를 최상으로 올려야 합니다.

> 참고: 기준서 §6.1 「요청 8 — 외부 콘텐츠 매입 데이터 유입 경로」가 **부분 수령**
> (0728 재무팀 정정)으로 되어 있어, 착수 조건은 이미 충족된 상태입니다.

### P1-04 감사컬럼 — 회원님의 「로그 남기기」 목표와 직결

> **P1-04 감사컬럼 / 상태이력 / 매출목표 / 여신한도 스키마**
> `created_by` · `updated_by` · `modified_at` **전 테이블 표준 강제**,
> 상태변경 이력 테이블, `sales_targets`, 여신한도. **논리삭제(soft delete) 표준 적용**

**중도금 판정 항목입니다.** 회원님이 하려던 「로그 남기기」가 여기 정확히 대응됩니다.
다만 **백엔드·DB 영역**이고, 프론트에서 할 수 있는 건 별개입니다.

### P1-07 RBAC — 00번에서 검증 완료

역할별 API 접근 테스트가 판정 기준인데, 프론트 권한 제어는 00번에서 **21항목 전부 통과** 확인.
(단 기준서는 **API 접근 제한**을 보므로 백엔드 검증이 본체입니다.)

## ★★★ 이 점검 작업의 상업적 의미

기준서 §6 원문 (강조는 원문):
> 특히 **레거시 소스·쿼리 미제공 상태에서 화면 캡처 기준으로 추정 구현한 업무규칙**
> (**매출일괄등록 처리·청구구분, 채권 대사, 물류단가 계산식** 등)은 **실제 로직 확인 후
> 재구현이 필요할 수 있으며, 이는 최초 견적의 1회 구현분을 초과하는 재작업입니다.**

**기준서가 지목한 3개 영역을 이번 점검에서 전부 검증했습니다:**

| 기준서가 지목한 위험 영역 | 점검 결과 |
|---|---|
| **매출일괄등록 처리** | 🔴 **결함 3건 발견** (금액 공식·마스터 대조·정가 하드코딩) → **전부 수정 완료** |
| **채권 대사** | ✅ 잔액 공식 정확 (16·17번 검산 통과) |
| **물류단가 계산식** | ✅ 레거시 verbatim 일치 (15번 검산 통과) |

→ **추정 구현 3개 중 2개는 정확했고, 1개(매출일괄등록)만 재작업이 필요했으며 이미 고쳤습니다.**

### 그리고 전제가 바뀌었습니다

§6.1 「확정자료 수령 현황(2026-08-03)」:

| 요청 | 자료 | 상태 | 영향 |
|---|---|---|---|
| **요청 1** | **기존 매출프로그램 소스코드 · DB 스키마 · 주요 쿼리** | **미수령** | **전 Phase (일정 순연 직결)** |
| 요청 2 | DSRE 연동 방식 확정 | 부분(서면 미승인) | P0-04 |
| 요청 3 | DS물류 이지어드민 API 규격 | 미수령 | 물류 연동 |
| 요청 4 | 프론트↔백오피스 상태 동기화 방식 | 미수령 | P1-08 상태머신 |
| 요청 5 | **부서별 화면·기능 접근권한 매트릭스** | 미수령 | P1-07 RBAC |
| 요청 6 | 물류 작업비 단가 체계·계산식 | 미수령 | 물류 작업비 |
| 요청 7 | 세트 조립 방식·다단계 BOM 여부 | 미수령 | P2-03 BOM |
| 요청 8 | 외부 콘텐츠 매입 데이터 유입 경로 | 부분(0728 정정) | **P2-08** |
| 요청 9 | 화면별 실사용 등급(폐기/최소재현/유지) | 미수령 | 마감관리 범위 |

**요청 1(레거시 소스)이 「미수령」인데, 지금 `~/Downloads/DsSales-main` 에 있습니다.**

- 요청 6(물류 단가 계산식)도 미수령인데, **레거시 `물류비계산2.vb` 에서 계산식을 확보**했습니다(15번)
- 요청 7(BOM 방식)도 레거시에 BOM 자체가 없음을 확인했습니다(03번, grep 0건)

→ **소스 수령 사실을 개발팀에 알리면 여러 항목의 「미수령」 상태가 풀립니다.**
   반대로, 소스 수령 전에 추정으로 만든 부분의 **재작업 정산 협의**도 이 문서 §6 근거로 진행 중입니다.

## 참고 — 문서가 정의한 용어
