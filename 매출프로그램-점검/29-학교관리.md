## ① ★ DSRE2 보존형 동기화 — 실제로 돌려봤습니다

요구 35p 핵심:
> '가져오기(DSRE2 동기화)'는 기존 '**전체삭제 후 재수입**' 방식에서, 매출프로그램 전용
> 데이터 보존을 위해 '**중복 동기화**' 방식으로 변경 필요

### 동기화 실행 전후

| | 전 | 후 |
|---|---|---|
| 전체 | 7 | **10** |
| 미사용 | 0 | **1** |
| 매출프로그램 전용 | 1 | **1** (변화 없음) |
| 거래처 정보 없음 | — | **2** |

### CLAUDE.md §4.6.16 의 6규칙 — 전부 확인

| # | 규칙 | 검증 |
|---|---|---|
| 1 | 매칭 키 = **거래처코드 + 학교코드** (2개) | 컬럼 2종 존재 |
| 2 | 키 있으면 → **DSRE 관리 필드만** 덮고 전용 필드 미변경 | 화면 안내 명시 ✅ |
| 3 | 키 없으면 → **신규 추가** | 7 → 10 (+3) ✅ |
| 4 | DSRE2 에서 사라지면 → **삭제 않고 '미사용'** | 미사용 0 → **1** ✅ |
| 5 | 매출프로그램 전용 → **동기화가 손대지 않음** | 전용 1 → **1 유지** ✅ |
| 6 | 거래처 못 찾는 원천 행 → **버리지 않고 유입 + 건수 리포트** | **거래처 정보 없음 2** ✅ |

**6규칙이 전부 실동작합니다.**

### 화면 안내가 규칙을 그대로 설명합니다

> 동기화는 **기존 데이터를 보존**합니다. DSRE2 가 관리하는 항목(학교/학원명·거래처명·도시·
> 지역·학교Y/N)만 덮어쓰고, **학교/학원구분·거래처구분·메모처럼 매출프로그램에서 입력한
> 값은 그대로 둡니다.** DSRE2 에서 사라진 항목은 **삭제하지 않고 '미사용'** 으로 바꾸며
> (**과거 매출 이력이 끊기지 않도록**), 매출프로그램 전용 데이터는 동기화 대상에서 제외합니다.

확인 다이얼로그에도 같은 내용이 반복됩니다 — **되돌릴 수 없는 동작이라 실행 전 재고지**입니다.

```
· 전용 보존 · 거래처 정보 없음
```

**8개 전부** 있습니다. CLAUDE.md 가 요구한
*"신규/갱신/변경없음/미사용/복구/**전용 보존**/**건너뜀(사유 포함)**"* 을 충족합니다.

> S5 가 FAIL 로 나온 것은 제 검색어 문제입니다 — 라벨이 `건너뜀` 이 아니라
> **`거래처 정보 없음`** 이었습니다. 사유를 그대로 이름으로 쓴 편이 더 명확합니다.

> **매칭 키를 2개로 정한 근거도 기록돼 있습니다** — 한때 '학교/학원구분'을 키에 넣었으나
> *"백엔드는 2개로 구현했고, 실덤프에서 충돌이 0건(`tbl_cust_ref` 76행이 전부 학원)"* 이라
> 백엔드에 맞췄고, **"학교 매핑이 유입되면 재검토 대상"** 으로 조건까지 달아뒀습니다.
