## ① 레거시 대비

레거시(`MainForm.vb`)는 **로그인이 없습니다.** 인증이 아니라 **IP 주소 판별**입니다.

```vb
' MainForm.vb:82
userTypeStr = DB.SelectValueQuery($"select userType from IPData where ip='{ipAddr}' ")
```

`UserTypeDefine`(Common.vb:21)은 3값 — `대성학력개발연구소` / `대성교재` / `대성물류`.
이건 **직무 역할이 아니라 법인 구분**이고, 이 값으로 메뉴 `ToolStripMenuItem.Visible` 을 켜고 끕니다.

| 항목 | 레거시 | 웹 | 판정 |
|---|---|---|---|
| 인증 수단 | IP 주소 → `IPData` 조회 | 아이디/비밀번호 | ⚠️ 의도적 차이 (전면 신규) |
| 사용자 식별 | 없음 (PC 단위) | 계정 단위 | ⚠️ 의도적 차이 |
| 권한 축 | 법인 3종 | 직무 역할 5종 × 조회/편집 | ⚠️ 의도적 차이 |
| 서버 재검증 | 없음 | 프론트는 UX만, 서버 검증 전제 | ⚠️ 의도적 차이 |
| 로그아웃 | 없음 | 있음(확인 다이얼로그) | 신규 |

**차이는 전부 의도된 것입니다.** 요구사항정의서에 명시돼 있습니다:

> 현행 IP기반 판별/전원 ROLE_ADMIN 하드코딩은 **이관이 아닌 전면 신규 설계 대상** (DB-29, BE-61, FE-11)

### 레거시에서 발견한 부수 사항 (참고)

- `where ip='{ipAddr}'` — **문자열 보간 SQL**. 요구사항정의서 "파라미터 바인딩 0건(BE-61)"과 일치
- `Finally` 블록에서 `UserType = 9` 로 덮음 — 예외 시 정의되지 않은 값이 들어감
- 웹은 알 수 없는 역할이 오면 **가장 낮은 권한(viewer)으로 강등**(`api.ts:60`). 레거시보다 안전한 처리

## ② 요구사항정의서 대비

정의서 1~38p에 **로그인/인증 화면 항목이 없습니다.** 대조할 조항이 없어 판정 보류(해당 없음).

관련 언급은 개발문서 로드맵 순번 12 「인증/RBAC 신규 설계(역할·부서·권한 매트릭스)」뿐이며,
CLAUDE.md §8에도 **인증 방식 미확정**으로 남아 있습니다.

- 백엔드는 httpOnly 쿠키 + refresh 회전 방식으로 구현됨
- 프론트는 sessionStorage 방식 → `auth/api.ts`·`auth/session.ts` 교체 필요
- 역할 5종은 **메뉴 구조에서 추론한 초안**, 업무 담당자 확인 필요

### 확인한 설계 의도

- `viewer`는 전 그룹 `*.view` 권한 보유 → **메뉴는 다 보이고 편집만 잠김**. 정상 동작
- `finance`는 `orders.view`·`logistics.view` 없음 → **메뉴 숨김 + 라우트 가드 이중 차단**
- 메뉴 숨김과 라우트 가드를 **둘 다** 검
- 오류 메시지가 아이디/비밀번호를 구분하지 않음 (계정 열거 방지)

## 남는 사항 (결함 아님)

1. **인증은 목업입니다.** `api.ts:118` — "실제 인증이 아닙니다. 비밀번호를 검사하는 척만 합니다."
   실서버 어댑터(`realAuth`)는 백엔드 DTO 실측으로 작성돼 있으나 미연결.
2. **역할 5종은 초안.** 실제 업무 분담과 맞는지 담당자 확인 필요 (CLAUDE.md §8).
3. **토큰이 sessionStorage.** 최종안은 httpOnly 쿠키 권장 (XSS 대비, §4.7).
4. **401 자동 재발급 미구현.** access 30분 만료 시 로그아웃됨 (갭리포트 §I-4).

이 4건은 모두 **개발자가 이미 문서에 기록해 둔 기지(旣知) 사항**입니다.
