## ① 레거시 계산식 — verbatim 확보, 웹과 일치

### 현재재고 (제품수불부.vb:104)

```sql
재고 = ( 입고 + 이월입고 − 이월매출 − 이월무가 − 이월유가 − 이월반품 + 이월폐기 + 이월대체 )
       − 매출 − 무가 − 유가 − 반품 + 폐기 + 대체
```

**표시 단계에서 부호를 뒤집습니다** (제품수불부.vb:88):
```sql
select …, 반품*-1 as '반품', 반품금액*-1 as '반품금액', …, 폐기*-1 as '폐기', 대체*-1 as '대체', 재고
```

→ **저장은 음수, 계산은 저장값 그대로, 표시는 ×(−1).**
   이것이 저장소 문서가 경고한 부호 함정의 정확한 실체입니다.

웹 목업(`datasets.ts:111`)은 값을 **양수로** 들고 있으므로:
```ts
balance = carried + inbound - sales - freeQty - paidQty + returns - disposal + transfer
```
→ `+반품 −폐기`. **부호 방향이 정확히 맞습니다.** 웹 주석의 설명과도 일치합니다.

### 순매출 (제품수불부.vb:101~102)

순매출금액 = 매출금액 + 교사용금액 + 반품금액

### 🔴 `-0` 표시 결함

조회 결과 1행에 **`-0`** 이 표시됩니다.

원인(`datasets.ts:106`):
```ts
const returns = (i % 5) * 8
const returnAmt = -(returns * 12_000)   // returns 가 0 이면 -0 (JS 음수 0)
```
`-(0 * 12000)` 은 JS 에서 **`-0`** 이고, `Intl.NumberFormat` 이 이를 **`"-0"`** 으로 냅니다
(node 확인: `(-0).toLocaleString() → "-0"`).

`shared/grid/format.ts` 의 `formatValue` 는 `null/undefined/''` 만 거르고 **음수 0을 정규화하지
않습니다.** 재무 리포트 화면에 `-0` 이 뜨는 건 사용자에게 오류로 보입니다.

**고치는 방법 2가지**
1. `format.ts` 에서 정규화 — `nf.format(value === 0 ? 0 : value)` (전 화면에 효과, 권장)
2. 목업에서만 수정 — `returns === 0 ? 0 : -(returns * 12_000)` (실서버엔 무효)

**1번 권장.** 실서버가 `-0` 을 내려줘도 방어됩니다. 기존 테스트
(`format.test.ts` — "`0` 이 빈칸이 되지 않을 것")와 같은 성격이라 테스트 추가도 자연스럽습니다.
