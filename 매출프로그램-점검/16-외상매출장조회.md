## ① ★ BE-52 확정 — 유사 화면 간 DML 차이

요구사항 24p 기술검증란:
> 조회 화면 자체는 **DML 없는 순수 조회**로 확인(BE-52). 단 25p 외상매출현황조회는
> **예외적으로 `INSERT INTO carrData`(이월 스냅샷)를 수행** — 유사화면 간 동작 차이 유의

**실측으로 확정**:

| 화면 | DML 문 수 |
|---|---|
| 24p 외상매출장조회 | **0건** — 순수 조회 |
| 25p 외상매출현황조회 | `INSERT INTO carrData` **1건** |

이름이 비슷한 두 화면이 **실제 동작은 다릅니다.** 25p 를 조회하면 이월 스냅샷이 **써집니다.**
→ 25p 테스트 시 반드시 확인할 지점입니다.

```
"채권을 상품군으로 나눈 데이터가 없다"고 판단해 미반영으로 남겼는데

```

**레거시 실측과 일치합니다.** 그리드 헤더에 `교재 / 모의고사 / IC / 특강` 이 실제로 있고,
2단 그룹 헤더(`공급 / 매출 / 교사용 / 반품 / 매입 / 취소 / 지급액` × 상품군) 구조입니다.

웹은 이를 `매출(교재) · 매출(모의고사) · 매출(IC) · 매출(특강)` 4컬럼으로 옮기고
**「상품군 분해」 체크로 여는** 방식(기본 13 → 17컬럼)을 택했습니다. 실측 확인:
```
13 → 17개 · 매출(교재), 매출(모의고사), 매출(IC), 매출(특강)
```

## ④ 잔액 계산 검산 — 통과

레거시 실측 공식(설정 파일에 기록됨):
> 잔액 = 이월 + 매출 + 교사용 + 반품 − 입금 (**반품은 음수 저장이라 더하면 차감**)

1행 실측:
```
전년도이월 200,000 + 매출 240,000 + 교사용 24,000 + 반품 (−12,000) − 수금 0
= 452,000  =  화면 잔액 452,000  ✓
```

**반품이 실제로 음수(−12,000)로 들어와 있어**, 01번에서 확인한 레거시 부호 규칙
(`반품·취소 → 수량·금액 모두 음수`)이 이 화면에서도 일관되게 지켜집니다.
