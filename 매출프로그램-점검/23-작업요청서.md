## ③ 레거시 대비

### 레거시 컬럼 (별칭 실측)
```
Box · seq · 거래순번 · 거래일자 · 거래처명 · 거래처코드 · 공급률 · 구분 · 금액 · 단가
· 도서명 · 도서코드 · 메모 · 반리스트 · 발송메모 · 발송일 · 분류 · 분류명 · 분류코드
· 삭제 · 수량 · **수량_교사용** · 수량리스트 · 완료 · 정가 · **출력** · **포장유형**
· 학교명 · 학교코드 · 회차리스트
```

### 웹 컬럼 (11)
```
요청일 | 등록처 | 거래처 | 학교/학원 | 분류명 | 도서명 | 수량 | 출고창고 | 발송구분 | 수령인 | 상태
```

| 레거시에만 있음 | 비고 |
|---|---|
| **Box** · **출력** | 요구 26p 「작업대기리스트(…**출력**/**Box**)」에도 명시. → **작업결과 화면(`logisticsScreens.ts`)에 구현돼 있습니다** |
| **수량_교사용** | 정상매출/교사용 라인 분리용. **10번 거래명세서에서 표 2개로 구현 확인** |
| **포장유형** | `Combo_PackType`(개별1/개별2/반별). 물류비 인원 산출(`FUNC_REQINWON_GET_PACKTYPE1/2`)의 키 — 15번 참조 |
| 반리스트·수량리스트·회차리스트 | 반×과목 다중행. `FE-07` 이 *"화면 제약이며 스키마 변경 불필요"* 로 판정 |
| 거래순번·삭제·완료 | |

**`Box`·`출력`·`수량_교사용` 은 다른 화면에 배치**돼 있어 누락이 아닙니다.
작업요청서는 **작업 지시·상태 관리**에, 작업결과는 **실적·수량 집계**에 나눈 구조입니다.

### 거래명세서 실시간 렌더 (FE-12) 확인

레거시 `작업요청서.vb` 에 `ReportViewer`/`rdlc` **29회** 등장 —
요구사항 `FE-12` 의 *"내장 ReportViewer 가 `salesData`/`distData` 원장 데이터로 실시간 렌더
(order 사이트 데이터 아님)"* 가 실측 확인됩니다.

웹은 이를 **별도 화면(`/sales/transaction-statement`)으로 분리**했습니다(10번 점검).
레거시는 작업요청서 안에 내장돼 있었으므로 **구조가 바뀐 것**이지만,
요구 26p 가 *"1페이지 거래명세서 연동 요구사항의 실제 화면"* 으로 연결해 두었고
10번에서 양식 정합을 확인했으므로 문제없습니다.
