## ① 레거시 계산식 — verbatim 확보 (`물류비계산2.vb:440~453`)

```sql
시험지합   = Σ REQCNT  WHERE 자재명 NOT IN ('OMR','단행본','책자','라벨')
시험지금액 = Σ (위) × RESULT.PAPER
OMR합     = Σ REQCNT  WHERE 자재명 = 'OMR'
OMR금액   = Σ (위) × RESULT.OMR
기타금액   = Σ(자재명 IN ('단행본','책자') × RESULT.ETC)
           + Σ(자재명 = '라벨'            × RESULT.LABEL)
기본작업비 = Σ 인원 × RESULT.BASIC
출고비     = Σ 인원 × RESULT.TRADE
금액합계   = Σ(시험지×PAPER + OMR×OMR + 기타×ETC + 라벨×LABEL)
           + Σ(인원 × (BASIC + TRADE))
```

요구사항 `BE-57` 이 인용한 식과 **정확히 일치**합니다.

### 주목할 두 가지

**1. 시험지는 부정형 정의입니다**
`자재명 NOT IN ('OMR','단행본','책자','라벨')` — 열거가 아니라 **나머지 전부**입니다.
자재 종류가 늘어나면 자동으로 시험지 단가가 붙습니다.

**2. 기타금액은 단가가 둘입니다**
단행본·책자는 `ETC`, 라벨은 `LABEL` — **서로 다른 단가를 곱한 뒤 한 컬럼에 합산**합니다.

**웹 목업이 이 세부까지 같습니다** (`datasets.ts:558~559`):
```ts
// 기타금액은 단행본·책자와 라벨의 단가가 달라 따로 곱한 뒤 더합니다.
const etcAmt = bookQty * prod.etc + labelQty * prod.label
```
주석까지 레거시 의도를 그대로 설명하고 있습니다.

### 인원은 DSRE2 저장 함수에서 옵니다

```sql
WHEN LOGCOST.PACKTYPE IN (1,2) THEN FUNC_REQINWON_GET_PACKTYPE1(REQI.REQ_CD)
WHEN LOGCOST.PACKTYPE = 3      THEN FUNC_REQINWON_GET_PACKTYPE2(REQI.REQ_CD)
```
`PACKTYPE` 은 `Common.vb:33` 의 `Combo_PackType = {"개별1","개별2","반별"}` 과 대응
(1·2 = 개별, 3 = 반별). **포장 방식에 따라 인원 산출 함수가 갈립니다.**

> DSRE2 연동 영역이라 이번 점검 범위에서는 제외했습니다. 다만 **인원이 금액합계의
> 두 항(기본작업비·출고비)을 좌우**하므로 연동 시 검증 대상입니다.

## ② 실데이터 검산 — 통과

조회 1행 실측:

| 항목 | 값 | 검산 |
|---|---|---|
| 시험지합 × 단가 | 300 × 180 | **54,000** ✓ |
| OMR합 × 단가 | 100 × 40 | **4,000** ✓ |
| 기타금액 | 0 | — |
| 기본작업비 | 인원 10 × 150 | **1,500** ✓ |
| 출고비 | 인원 10 × 90 | **900** ✓ |
| **금액합계** | 54,000+4,000+0+1,500+900 | **60,400 = 화면값** ✓ |
| 자재합 | 시험지 300 + OMR 100 + 기타 0 | **400 = 화면값** ✓ |

**금액합계·자재합 모두 화면 표시값과 일치**합니다.
