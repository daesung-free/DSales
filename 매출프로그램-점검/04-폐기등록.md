## ★ 요구사항정의서의 채번 규칙이 실제와 다릅니다

10p 원문:
> 거래순번 채번(**YYYYMMDD-P0xx**) (예: 20260626-P001)

**레거시에 이 형식이 없습니다.** `P0[0-9]` 패턴 grep 결과 폐기 전표번호는 0건이고,
매칭된 건 전부 파일명·조회일자 포맷이었습니다.

레거시의 실제 채번(`UC_TabPages.vb:167~173`):
```vb
' 같은 (날짜 + 거래분류 + 거래유형 + 거래처)의 기존 tradeSeq 목록을 조회
Dim seqList As ArrayList = GetSeqList(sqlString)
seqList.Add(seqList.ToArray.Max + 1)          ' ★ 앱 메모리에서 Max+1
ComboBox_Seq.SelectedItem = seqList.ToArray.Max
```

- `tradeSeq` 는 **정수**입니다(`ConvDB.vb`: `tradeSeq int`). 문자열 전표번호가 아닙니다
- 범위는 **(일자 × 거래분류 × 거래유형 × 거래처)별 순번**입니다
- **사용자가 콤보박스에서 고를 수도 있습니다** — 자동 발번 전용이 아닙니다

→ 요구사항 sheet2 ⑤ 「채번 규칙」이 **"통합 확인 중 – 검증 필요"** 로 표시돼 있었는데,
  **실측 결과 4종(S+MMDD / I+MMDD / YYYYMMDD-P0xx / OUT-) 전부 레거시엔 실체가 없습니다.**
  기획서 목업 화면에서 읽은 **신규 규칙**입니다. 이관이 아니라 신설로 봐야 합니다.

### 동시성 지적은 정확했습니다

요구사항 `DB-51`·이슈#38:
> 기존 tradeSeq/collSeq(**앱 메모리 Max+1**) 방식은 웹 동시접속 환경에서 경합·중복 발생 위험 — 반드시 폐기

**실제 코드가 정확히 그렇습니다.** 위 `seqList.ToArray.Max + 1` 이 메인 경로입니다.
(`CommonDB.vb` 의 `GetTradeSeq()` 함수는 **전부 주석 처리**된 죽은 코드였습니다 —
지적 대상은 이쪽이 아니라 폼 안의 인라인 로직입니다.)

### 🔴 폐기 사유 선택지가 다릅니다

레거시(`Common.vb:30~32`) — **법인별로 다릅니다**:

| 법인 | 사유 |
|---|---|
| 대성학력개발연구소 | 재고부족 · 주문착오 · 파본 |
| 대성교재 | 재고처분 · 주문착오 · 파본 |
| (IC/취소) | 취소 · 주문착오 · 파본 |

웹 — 단일 5종: **파본 · 반품손상 · 기한만료 · 재고정리 · 기타**

- 공통은 **`파본` 하나뿐**입니다
- 레거시의 **`주문착오`가 웹에 없습니다** — 3개 법인 전부가 쓰던 값입니다
- 웹의 `반품손상`·`기한만료`·`기타`는 레거시에 없는 신설 값입니다
- 레거시의 **법인별 분기**가 웹에선 사라졌습니다(마감 단위가 전사 통합으로 확정됐으므로
  의도적일 수 있으나, 값 목록 자체가 달라진 것은 별개 문제)

「기존이관-무수정」 화면인데 **선택지가 교체됐습니다.** 과거 데이터에 `주문착오`·`재고부족`·
`재고처분`이 들어 있다면 웹 필터로 걸리지 않습니다.

**→ 확인 대상.** 발주처가 사유 목록 개편에 동의했는지, 아니면 추론으로 만든 값인지.
