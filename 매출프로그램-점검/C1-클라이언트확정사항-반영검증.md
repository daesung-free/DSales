## B. 재무팀 정정 2026-07-28 (요구사항정의서 sheet2 ⑫) — 6건

### B-1. 회계 용어 표준화 — ⚠️ 해석 여지

**확정 원문**:
> 정정 전: 공급가액/순공급가액 등으로 용어 통일 필요 요청
> **정정 후: 별도 회계용어 없음 — '금액'·'총금액'으로만 표기, 표준화 작업 불필요(스코프 축소)**
> 비고: 재무팀요청서 3.6 항목 **삭제 가능**

**코드 실측**:

| 화면 | 라벨 |
|---|---|
| 6p 주문 상세 (등록) | **금액 · 세액 · 총액** ✅ 확정대로 |
| 통합매출조회 | 공급가액 |
| 매출액 정리 | 공급가액 |
| 순매출 조회 | 순공급가액 · 교사용 공급가액 · 반품 공급가액 |
| 매출 등록 | 정산 공급가액 |

→ 화면 라벨에 **「공급가액」 계열 10개** 사용 중.

**두 가지로 읽힙니다:**
- (a) *"금액·총금액으로만 표기"* = **이름을 바꾸라는 지시** → 조회 화면들이 미반영 ❌
- (b) *"표준화 작업 불필요, 요청서 3.6 삭제 가능"* = **작업 취소** → 기존 라벨 유지해도 무방 ✅

**(b)에 무게가 실립니다** — 비고가 "항목 삭제 가능"이고, 요구사항 7p·12p 의 데이터 항목란은
여전히 「공급가액」을 씁니다(정정 이전 작성분일 수 있음).
그리고 **정정이 명시한 6p 등록 화면은 실제로 금액/세액/총액**입니다.

→ **확인 대상**: 조회 화면 라벨을 금액/총금액으로 바꿔야 하는지, 현행 유지인지.
   바꾼다면 10곳 + 엑셀 양식까지 연쇄 영향이라 사전 합의 필요.

### B-2. 세액 계산 로직 — ✅ (단 1곳 위반)

**확정**: 금액=정가×공급률 / 세액=금액×10% / **세액 자동산출 안 함 — 기본값 0, 필요 시 수동입력**

`shared/money.ts` 주석에 확정 문구가 그대로 인용돼 있고 `taxOf()` 가 그 규칙을 구현.

> 🔴 **예외 1건**: 08번에서 확인한 **매출일괄등록**(`api.ts:641`)이 정본을 안 쓰고
> **폐기된 옛 공식(단가 반올림 후 곱)** 을 사용 중. 이미 수정 후보로 기록.

### B-3. 매입 데이터 매칭 방식 — ✅

**확정**: 자동 매칭 불가 → **자동 파서 대신 수기 입력 보조**

웹에 매입 자동 파서가 **없습니다** — 확정대로입니다.

> ⚠️ 다만 `docs/레거시-대비-구현현황.md` §5-C 향후과제에 *"매입원가 엑셀 업로드 화면 —
> 백엔드 파서와 함께"* 가 **남아 있습니다**(03번 기록). 문서만 정정 필요.

### B-4. 매입 등록 위치 — ❌ **미반영**

**확정** (★가장 큰 정정):
> 별도 화면 신설 없음 — **8p 입고/대체등록에 '매입' 구분값 필드만 추가**,
> 해당 입고 내역이 16p 에 자동 연결

- 8p `/orders/inbound` — `매입` grep **0건. 미구현** ❌
- 16p `/sales/net` — 매입액(B)·입고수량·이익률 컬럼 **완성** ✅

**수신 측은 준비됐는데 발신 측 필드가 없어 연결이 끊겨 있습니다.**
(03번 기록 → 12번에서 우선순위 상승 확인)

### B-5. 도서관리 「수불부노출」 필드 — ✅

**확정**: PPT 기획안에 필드 정상 포함 → 기획서 기준으로 개발이 맞음

**요구사항 32p 데이터 항목 15종 전수 대조 결과 — 전부 존재**:
```
분류코드·분류명·도서코드·도서명·상품년도·학년·대분류·상품구분
·Web게시·면세·정가·공급률·매출구분·사용여부·수불부 노출
```
> 최초 미구현으로 판정했는데 제 검색 오류입니다 — 라벨이 **「수불부 노출」(띄어쓰기)** 였습니다.
> CLAUDE.md §4.6.4 의 *"우리가 기획서 기준으로 구현해 둔 것이 맞으므로 조정할 것이
> 없습니다"* 주장이 **사실입니다.**

### B-6. 물류팀 인터뷰 — 해당 없음
